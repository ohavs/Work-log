## שלב 2: בנייה ל־Play 🤖 (+👤 סודות ו־Firebase)
1. **שתי גרסאות** (product flavors): `github` = מה שיש היום (APK, מעדכן). ‏`play` = ‏AAB, בלי מעדכן והרשאות התקנה, R8.
   בצד ה־JS: `scripts/build-web.mjs` מקבל דגל `--play` ומחליף את `update.js` ב־stub.
2. **חתימה:** Play App Signing (ברירת המחדל), עם מפתח העלאה חדש שאני מייצר ושולח לאוהב. 👤 מוסיף שני Secrets:
   `UPLOAD_KEYSTORE_BASE64`, ‏`UPLOAD_KEYSTORE_PASSWORD`.
3. **⚠️ התחברות Google בגרסת Play:** גוגל חותמת מחדש את האפליקציה, ולכן ה־SHA-1 משתנה וההתחברות **תיכשל** אם לא:
   👤 Play Console ← App integrity ← להעתיק את SHA-1 של App signing key ושל Upload key ←
   Firebase ← Project settings ← האפליקציה `app.worklog.hours` ← Add fingerprint (שניהם) ← להוריד `google-services.json` חדש ולשלוח לי.
4. **העלאה אוטומטית:** job ‏`play` ב־`android.yml` (או `release.yml` נפרד), כמו ב־Currency: ‏`r0adkll/upload-google-play`, ‏versionCode עולה, mapping.
   👤 **חשבון השירות של Currency** (פרויקט `currency-play`) יכול לשמש גם כאן: Play Console ← Users and permissions ←
   חשבון השירות ← לתת הרשאות גם לאפליקציה החדשה, ולהוסיף את אותו JSON כ־Secret ‏`PLAY_SERVICE_ACCOUNT_JSON` בריפו הזה.
5. **בדיקת עשן ב־CI:** להריץ את בילד ה־play באמולטור (כמו `smoke.yml` ב־Currency): פתיחה, כניסה/יציאה, הוספת רישום, הגדרות, ייצוא. להיכשל על קריסה.
6. **בדיקות יחידה:** אין כרגע אף בדיקה. הפונקציות הטהורות כבר מופרדות (`mergeCollection`, ‏`mergeSettings`, ‏`finance.js`, ‏`workdays.js`, ‏`reminders.plan`), אז להוסיף `node --test` ולהריץ ב־CI.
